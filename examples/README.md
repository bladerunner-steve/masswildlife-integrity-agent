# Example integrity badges (synthetic runs only)

Generated by `eval/make_examples.py` from synthetic runs: an offline fake API over pseudonymized fixture clones,
an in-memory database and a throwaway notary key. No production data, key or vault was involved. Open each
`index.html` in a browser.

| Folder | Run | Configuration | Verdict |
|---|---|---|---|
| `verified/` | clean, authorized run | C (crypto + policy + evidence) | VERIFIED WITHIN SCOPE |
| `failed/` | signed but unauthorized run (`place_id` added to the request) | C | VERIFICATION FAILED, localized to step 1 |
| `false-assurance/` | **the same** unauthorized run | A (crypto only) | VERIFIED WITHIN SCOPE: a false assurance |
| `insufficient/` | a run whose PR2 receipt left out one raw response page | C | INSUFFICIENT EVIDENCE |

`failed/` and `false-assurance/` come from the same trace. Every signature in it is valid, so cryptographic
verification alone passes it. Only the policy layer sees that the request broke policy.
